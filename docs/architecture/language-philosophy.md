# Aria 言語理念

Aria は、物語を書くために最小化した Rust 風の管理可能性を持つ言語です。作者が
画面・音・分岐を短く書けることと、長編で資源・状態・制御フローが壊れないことを
同時に優先します。

具体的な構文は [Aria 言語仕様](../spec/aria.md) が正です。この文書は、なぜその形を
選んだかを定義します。

## 問題の監査と結論

| 以前の問題 | 失敗の理由 | 現在の決定 |
|---|---|---|
| 世代ごとのヘッダー、`strict`、互換モード | 同じ拡張子なのに解析・診断・実行経路が変わる | `aria;` 一つ。モード選択なし |
| 行指向 parser と構造化 parser の同居 | 作品ごとに意味論とエラー品質が変わる | 単一の構造化 front end だけで parse/analyze/lower |
| Sprite ID は文字列、寿命は作者の記憶頼み | 二重削除、リーク、場面をまたぐ偶発共有を生む | `Node` は一所有者。`drop` と字句スコープで決定的解放 |
| 暗黙の可変 sprite 操作 | どの文が画面状態を変えるか読めない | `move &mut n`、`hide &mut n` など明示借用 |
| 分岐・ループの資源状態が未定義 | 経路によって Node が生存/消滅し、再現性が壊れる | 継続する経路の所有状態を合流時に一致させる |
| VM 内の layout/UI DSL | 作品 UI とランタイム表示が二重化する | Aria は意味的 `screen` のみ。表示は React/Tauri/Web package |
| 互換 host opcode | ビルド済み内容がホスト依存・非決定的になる | opcode と runtime bridge を廃止し、ARIAC7 で境界を切る |

## 言語の役割

Aria が所有するのは、物語の状態遷移です。

1. scene、台詞、待機、選択、ジャンプ
2. 背景、音、演出、所有 Node の生成と解放
3. セーブ対象の `state`、既読・章・CG などの意味的状態
4. `screen` による presentation への意味的な要求

Aria が所有しないのは、見た目そのものです。

1. DOM/React/Tauri のレイアウト
2. フォント選択、色、余白、レスポンシブ規則
3. アクセシビリティ tree と操作 affordance
4. 作品固有のメニュー・タイトル・ギャラリーの画面実装

この境界により、ランタイムは決定論的な物語 VM のまま、プレゼンテーションは各作品に
必要な品質で進化できます。

## Rust から受け継ぐ規則

### 可変性は既定で閉じる

`let` と `state` は不変です。変更可能な値だけ `mut` を宣言します。これにより、
分岐条件や進行値の書き換えをレビュー時に見つけやすくします。

### Node は affine な所有資源

Node は「GC の対象」ではなく「画面に対する予約」です。Node はコピーできず、
移動・`drop`・スコープ終了のどれかで消費されます。コンパイラが `SpriteRemove` を
生成するため、停止フレームでも回収待ちの仕事や GC pause を作りません。

### 可変操作は借用で表す

画面資源を動かす操作は `&mut` を要求します。一時的に名前を付けたい場合は
`borrow mut owner as alias { ... }` を用います。貸し出し中は所有者を使えないため、
同じ Node を別の場面操作が同時に変更する余地がありません。

### 制御フローは寿命を壊さない

`if` の合流点に届く全経路は同じ Node 所有状態でなければなりません。`while` は
ゼロ回実行されうるため、継続する反復で外側 Node を消費できません。これは著者に
少し制約を課しますが、経路依存のリークや二重解放をコンパイル時に止めます。

## 設計ルール

1. 一つの `.aria` は一つの文法・一つの型規則・一つの実行意味を持つ。
2. 作用を持つ操作は明示する。特に Node 変更は `&mut`、所有権破棄は `drop`。
3. 暗黙の scene fallthrough、再帰的 scene call、未定義の UI layout を作らない。
4. コンパイラの診断コードは CLI、エディタ、CI で同じ意味を持つ。
5. バイトコード ABI の更新は source mode を増やす理由にしない。必要なら format を切る。
6. 互換レイヤーを追加して新仕様を曖昧にしない。変換器は外部ツールであって runtime
   dependency ではない。

## 非目標

- NScripter/BASIC/C# の文法との互換
- opt-in strictness や project ごとの言語モード
- GC による Node 寿命管理
- source からの UI layout・テーマ・widget tree の宣言
- 便利だが非決定的な host callback opcode

新しい構文や機能は、上記の規則を保ったまま [言語仕様](../spec/aria.md) と同じ変更で
追加します。
